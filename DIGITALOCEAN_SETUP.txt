WEDDINGSNAP - DIGITALOCEAN SETUP, COMMAND BY COMMAND
====================================================

Run the commands in order. Lines starting with # are notes; don't paste them.
Change the 3 values in PART 0 to yours. Everything after that is copy-paste.
(More explanation for each step: DEPLOY.md)

----------------------------------------------------------------------
PART 1 - CLOUDFLARE R2  (in the browser, no commands)
----------------------------------------------------------------------
# 1. dash.cloudflare.com -> R2 Object Storage -> Create bucket -> name: weddingsnap-prod
#    (Public access: OFF)
# 2. Create bucket -> name: weddingsnap-backups
#    Settings -> Object lifecycle rules -> Add rule -> delete objects 30 days after upload
# 3. weddingsnap-prod -> Settings -> Object lifecycle rules -> abort incomplete multipart uploads after 1 day
# 4. R2 -> Manage API tokens -> Create API token
#      Permissions: Object Read & Write
#      Buckets: weddingsnap-prod AND weddingsnap-backups
# 5. Write down: Account ID, Access Key ID, Secret Access Key  (the secret is shown only once)

======================================================================
EVERYDAY COMMANDS  (on the droplet)
======================================================================
# Is the app running?
systemctl status weddingsnap --no-pager

# Live logs (Ctrl+C to stop)
journalctl -u weddingsnap -f

# Last 50 log lines
journalctl -u weddingsnap -n 50 --no-pager

# Restart the app (gunicorn)
sudo systemctl restart weddingsnap

# gunicorn settings (threads, timeout): /srv/weddingsnap/gunicorn.conf.py, then restart

# Index all waiting photos from the command line
sudo -u weddingsnap /srv/weddingsnap/.venv/bin/python /srv/weddingsnap/manage.py index_photos

# Backup now
sudo -u weddingsnap /srv/weddingsnap/.venv/bin/python /srv/weddingsnap/manage.py backup_db

# Memory and disk
free -h
df -h /

# HTTPS certificate renewal test (renews automatically)
sudo certbot renew --dry-run


======================================================================
RESTORE THE DATABASE FROM A BACKUP  (on the droplet)
======================================================================
# See available backups:
ls -lh /srv/weddingsnap/backups/

# Replace the file name below with the one you want:
sudo systemctl stop weddingsnap
cd /srv/weddingsnap
sudo -u weddingsnap cp db.sqlite3 db.sqlite3.before-restore
sudo -u weddingsnap sh -c 'gunzip -c backups/weddingsnap-YYYY-MM-DD-HHMMSS.sqlite3.gz > db.sqlite3'
sudo rm -f db.sqlite3-wal db.sqlite3-shm
sudo systemctl start weddingsnap


======================================================================
IF SOMETHING GOES WRONG
======================================================================
# setup.sh fails at the HTTPS step:
#   -> DNS not pointing at the droplet yet:  dig +short $DOMAIN   must show the droplet IP
#   -> or ports 80/443 not open in the DigitalOcean Firewall. Fix, then run setup.sh again.
#
# Site shows "502 Bad Gateway":
journalctl -u weddingsnap -n 50 --no-pager
#   -> usually a typo in /srv/weddingsnap/.env. Fix it, then:
sudo systemctl restart weddingsnap
#
# "Cloudflare R2 is partly configured" in the logs:
#   -> one of the R2_ values in .env is empty
#
# Upload fails with error 413 (too large):
sudo nano /etc/nginx/sites-available/weddingsnap
#   -> raise client_max_body_size, save, then:
sudo systemctl reload nginx
#
# Can't SSH in:
#   -> DigitalOcean -> droplet -> Access -> Launch Droplet Console (terminal in the browser)
#
# Indexing too slow:
#   -> DigitalOcean -> droplet -> Resize -> "CPU and RAM only" -> 8 GB / 4 vCPU
#      (the app uses the extra cores automatically after restart)
